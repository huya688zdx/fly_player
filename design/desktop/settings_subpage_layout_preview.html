设置二级页 · 宽窗口布局方案

场景：并行窗口 关闭，桌面宽窗口单屏打开「储存管理」。橙色斜纹 = 当前被浪费的空白区。四个方案内容完全一致，只变容器与排版。窗口内容区按 1680px 宽模拟。

A · 现状 整个二级页（连 AppBar）锁 940px 居中 —— 你截图的样子 改动成本 0（对照基线）
问题：返回钮离左缘一大截、两侧空洞无解释性，越宽的屏幕越像坏了。
B · 顶栏拉通 返回钮 + 标题 + 刷新横贯整个内容区，正文仍 940px 居中 改动成本 低 · 只动子页容器一处
顶栏把宽度「钉」住了，下方居中变成有意图的排版。实现：把头部从子页 Scaffold 提到设置区容器统一绘制（返回钮本来就该贴边），子页去 AppBar 只留正文。所有二级页一处改完。
C · 自适应双列 正文放宽到 1240px，卡片重排两列 —— 最「桌面原生」 改动成本 中高 · 容器 + 各子页内容响应式
空间被真正用起来：总占用 + 环形图并排，分类详情双列。观感与首页分组网格同语言，但要给 11 个子页各自做宽屏排版（列表型页面如日志/下载收益小），工作量最大。
D · 居中面板卡 保持 980px，但整页装进一张浮起的面板卡，空洞变成「舞台」 改动成本 最低 · 只改子页容器装饰
不挪内容，把「空」变成设计：面板浮在氛围底上（同筛选弹层、浮窗的面板语言），空白读作留白而非缺失。可与 B 叠加（面板 + 拉通顶栏）。

组合建议：B + D（顶栏拉通 + 面板卡）成本依然只有子页容器一处，观感完整；若追求真正的桌面密度再上 C。手机 / 平板形态不受影响——窄视口下面板退化为通栏，顶栏回到子页自带 AppBar。
