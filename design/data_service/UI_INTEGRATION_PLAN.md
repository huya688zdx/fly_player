# 飞翔账号与原播放器界面融合

目标：沿用原有影视首页、继续观看、海报、详情、选集和播放，把统一账号与来源管理融入现有导航。

设计依据：用户明确要求新页面与原播放器融合。当前 MainNavigation 按是否登录飞翔替换首页，导致 NAS 列表和原媒体首页并存；同步详情又要求跳到原详情才能播放。

采用恢复原首页并嵌入来源切换的方案。单纯给 NAS 列表换颜色仍保留重复路径；把整套原媒体详情重写为 NAS 数据页会扩大范围并丢失原交互，因此不采用。

实施分工：

- [x] 主线程：MainNavigation 统一使用 MediaListScreen；首页标题显示当前来源并提供来源切换、账号、已同步节目和观看统计入口。飞翔模式移除原媒体退出按钮，账号操作统一进入账号页；本地连接/副窗保持原路径。
- [x] 账号页：复用主题、氛围背景和品牌资源，明确账号与媒体来源层级。主按钮进入媒体库，管理动作收进菜单或展开区。单地址直接选用，多地址按局域网/HTTPS/VPN选择；成功返回原首页，失败留在页面说明问题。
- [x] 同步节目页：改为响应式海报网格；卡片直接进入原媒体详情，“同步信息”作为独立次级入口；继续保留鉴权图片、搜索分页和账号隔离。
- [x] 设置页：统一“账号与媒体来源”“已同步节目”“观看记录同步”文案和路由，保持现有设置分组外观。
- [ ] 验证：来源切换和失败/取消交互、迟到请求与账号隔离、现有首页/桌面导航回归；静态分析、便携 Release 构建；实际窗口验证首页、来源切换、节目详情和播放。

公开共用接口：`activateFlyBinding(BuildContext, FlyAccountController, Map<String,dynamic>) -> Future<bool>`，处理选择地址与激活，不负责导航。页面仅在返回成功后决定是否退出。

所有开发工具、依赖、缓存、临时文件和构建均留在 E 盘。保留已有工作区改动；按用户追加要求，NAS 设置、弹幕获取和详细统计由并行分工实现并集成；播放器内核和显卡驱动未改动。
