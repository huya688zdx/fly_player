# 飞翔数据服务 P1 客户端

本文保留原 P1 参考工作树的设计与验证历史。主目录当前统一账号、绑定与自动补传入口及本次实际验证，以 [P2_CLIENT.md](P2_CLIENT.md) 为准；下述 1237 项和代理测试不代表本次 main 的结果。

入口：设置 → 数据与下载 → 飞翔数据服务。Windows 与 Android 使用同一个设置页面和原有导航。

## 使用流程

1. 在 NAS 网页创建独立的数据服务帐号。在播放器输入服务根地址、数据帐号、密码和设备名。密码只用于登录；访问令牌与安装身份使用现有 Android Keystore 通道 / Windows DPAPI 后端保存，不使用媒体服务凭据。
2. 核对页面显示的当前本地统计范围。曾通过网页导入的历史，先读取服务端数据集，选择原始来源并“关联匹配历史”。匹配使用原历史 ID、视频 ID、起止事实及原始载荷，不按标题猜测归属。事实不符时整次关联回滚，页面显示冲突记录 ID。
3. 明确确认本地归属及剩余历史未曾导入。客户端会分页读取所有数据集身份清单，包括墓碑和退役来源；遇到已有身份会阻止创建新来源重复上传。
4. 点击“立即同步”。仅 `applied` 回执记为成功；网络失败、拒绝或非 applied 回执都保留原始 JSON 快照。下一次手动重试发送相同字节和序号，再次点击同步才发送之后的新变化。

## 持久化与一致性

统计数据库从 v3 升到 v4，原五张统计表和旧记录 ID 保留。新增 `fly_datasets`、`fly_record_provenance`、`fly_write_context`、`fly_sync_state`、`fly_scope_binding`。旧历史初始归属未确认。新会话 ID 和新来源 ID 使用安全随机 UUID v4。

原始历史 INSERT / INSERT OR REPLACE / UPDATE 由 SQLite 触发器在相同事务内维护来源、记录版本和数据集水位；元数据回填更新历史时也触发版本更新。来源表不通过级联删除跟随 REPLACE 丢失。SQL 不依赖 Android 旧系统缺少的 UPSERT 语法。

同步先等待当前本地会话落盘和已有元数据回填，随后在单个数据库事务内读取完整当前范围并持久化不可变待重试包，事务结束后才注册来源或发送 HTTP。媒体帐号切换先收口并等待旧范围本地统计，再重绑数据库；同步操作固定数据库连接并校验范围世代，防止读写跟随帐号切换。

数据库异步打开期间若范围改变，会关闭旧句柄并重新打开当前范围。旧版文件名清洗/截断可能让不同媒体帐号指向同一文件；第一次明确确认/关联时，同一事务保存完整规范化媒体范围的 SHA256。之后确认、关联、创建快照和待重试包返回均要求完全一致，不能覆盖已有绑定。这是同步侧的防护，没有更名现有统计文件，也不能修复升级前已混入的历史；页面要求用户先核对归属。

导入关联保留远端 `metadata_snapshot` / `source_ref` / `quality_flags` / `rules_version`，并在本地载荷补充了旧导入缺少的字段时增加版本。已知墓碑继续使用原身份，服务端删除屏障阻止复活。缺失行不表示服务端删除。

## P1 边界

- 仅手动同步，没有自动轮询、播放心跳或原媒体进度协议改动。
- 仅导出当前明确确认的本地统计范围。P1 完整快照上限 10000 条、4096 个来源、未压缩 8 MiB；超限先报错，不截断上传。
- 数据库每次重新打开后的新记录使用新写入来源，因此这些新记录首次同步仍需再次确认归属。已有记录来源保持不变。安装身份在安全存储中跨正常启动保持稳定，不会每次启动新建服务端设备。
- 数据库单独恢复保留旧来源，新写入来源另建。完整应用备份 / 跨设备复制安全凭据的恢复行为尚需 Windows、Android 实机验证，不能把复制的令牌作为新安装身份的证明。
- 从另一设备恢复的待重试包会阻止上传，需由原设备完成重试。退役来源的删除屏障会明确阻止重新上传；没有更换来源绕过删除的入口。
- 旧版媒体播放量是估计值。没有伪造 `wall_watch_ms`、精确观看时间或季度完成率。BIF、精确 OP/ED、弹幕同步均不在本阶段。
- 旧样本导入之后本地原始事实发生变化时，首次关联会阻止并要求核对，而不会悄悄覆盖服务端事实。

## 验证命令

全部运行时和缓存使用 E 盘。在 PowerShell 先点加载环境脚本，再执行：

```powershell
. E:/fly_play_recovere/fly-data-service/scripts/enter-env.ps1
flutter --no-version-check pub get --enforce-lockfile
$env:FLY_TEST_PYTHON = 'E:/fly_play_recovere/fly-data-service/.venv/Scripts/python.exe'
$env:FLY_TEST_BACKEND = 'E:/fly_play_recovere/fly-data-service'
flutter --no-version-check test --no-pub --reporter expanded
flutter --no-version-check analyze --no-pub
& $env:FLY_TEST_PYTHON test/services/check_sync_schema.py
```

`test/services/check_sync_schema.py` 在 Flutter SDK 尚未就绪时直接执行生产迁移 SQL，验证 INSERT、REPLACE、元数据更新、事务回滚及本地删除不推进服务端删除屏障。已观察对应旧实现失败，再验证新实现通过。

真实 API 集成测试使用上述两个 `FLY_TEST_*` 环境变量启动临时本机后端，全部数据为合成历史、临时帐号和临时目录，测试结束后关闭服务并清理。未配置环境变量时该项会跳过。它验证导入、阻止重复确认、关联、首次同步、修订、新 UUID 记录、墓碑，以及整数 `0` 与 SQLite `0.0` 的兼容性。
