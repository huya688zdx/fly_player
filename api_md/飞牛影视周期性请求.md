# 飞牛影视前端周期性/定时请求清单

> 承接 [飞牛影视API文档.md](E:\NAS\飞牛影视API文档.md)。本文单独列举前端**自动周期性**发往后端的通信（轮询、定时上报、续期心跳），包含执行周期、触发/停止条件、请求体和触发后的详细行为。
> 依据：前端 JS bundle 静态分析（定时器常量均已还原出具体数值）+ NAS nginx 访问日志实测佐证。分析日期 2026-09-05。

## 0. 总览

| # | 请求 | 方法 | 周期 | 场景 | 免签名 |
|---|---|---|---|---|---|
| 1 | `/v/api/v1/task/running` | GET | **每 3 秒** | 管理员登录后停留在主界面/媒体库页 | ✅ |
| 2 | `/v/api/v1/search/indexStatus` | GET | **每 3 秒** | 搜索/设置界面挂载期间 | ❌ |
| 3 | `/v/api/v1/play/record` | POST | **每 15 秒**（起播 1 秒首报） | 播放器播放中 | ✅（精确匹配） |
| 4 | `/v/api/v1/media/p`（media.transcodeStatis） | POST | **每 30 秒** | **仅转码会话**；直连播放时由浏览器本地计算，不发请求 | ✅（/media/ 前缀） |
| 5 | `/v/api/v1/stream`（stream.playback 续期） | POST | 定时器 30 秒一查，**过期前 30 秒内才真正发** | 直链模式播放中 | ❌ |

没有 WebSocket 心跳、没有 keepalive 类请求——应用层的 WebSocket 引用只存在于 flv.js 的 ws:// 直播流传输器里，与后端无心跳交互。

## 1. `GET /task/running` —— 全局任务进度轮询（3 秒）

- **周期**：`pollingInterval: 3*1e3`（3 秒），主 bundle `74c95604…js`。
- **触发条件**（源码变量 `u` 为 false 时才轮询）：`isAdmin && token 存在` 且当前页面是主界面/媒体库页；登录页、初始化页、（除媒体库设置外的）设置页、全屏播放页均**不轮询**（`manual:true`）。
- **请求**：`GET /v/api/v1/task/running`，带 authx 也不带均可（该端点在**免签名精确列表**里，专为高频轮询设计）。
- **触发后行为**：返回当前运行中任务数组，前端按类型分组：`globals / libraries / scrapStream / useless / fileExistCheck / rescrap / refreshMetadata / thumb / subtitleExtract`，驱动顶栏任务中心角标与各类进度条（刮削、元数据刷新、缩略图生成、无用文件清理等）。
- **停止**：离开页面（组件卸载）或权限状态变化（`refreshDeps:[u]` 重置轮询）。

## 2. `GET /search/indexStatus` —— 搜索索引状态轮询（3 秒）

- **周期**：`pollingInterval: 3*1e3` + `throttleWait:100`（3 秒），主 bundle `74c95604…js`（hook `LB`）。
- **触发条件**：挂载了该 hook 的界面（搜索、设置/媒体库相关页面）。
- **请求**：`GET /v/api/v1/search/indexStatus`（正常签名链路）。
- **触发后行为**：读取 `data.rebuilding` 布尔值——索引重建任务进行中时 UI 显示"重建中"状态；重建完成后由界面刷新结果。
- **停止**：组件卸载。

## 3. `POST /play/record` —— 播放进度定时上报（15 秒）

**核心常量**（共享 chunk `5e689e2b…js`，源码常量名原样保留）：

| 常量 | 值 | 含义 |
|---|---|---|
| `PLAYER_STARTUP_RECORD_DELAY` | `1e3`（1 秒） | 起播后首次上报延迟 |
| `PLAYER_RECORD_INTERVAL` | `15e3`（**15 秒**） | 周期上报间隔 |
| `PLAYER_MIN_RECORD_INTERVAL` | `1e3`（1 秒） | 去重最小间隔 |

- **触发流程**（普通播放与直播各有插件，逻辑一致，chunk `bf29a647…` 两个变体）：
  1. 播放器派发 `PLAY` 事件 → 清掉旧定时器 → `setTimeout(首次上报, 1秒)` → `setInterval(周期上报, 15秒)`；
  2. 每次触发调用 `postRecord()`；
  3. 播放器派发 `PAUSE` / `ENDED`（停止）事件 → **立即补报一次**，随后停表；
  4. 播放器 `destroy` 时清理定时器。
- **请求体**：
  - 普通播放：`{item_guid, media_guid, ts:当前播放位置, play_link?, resolution?, bitrate?, audio_guid?, direct_link_audio_index?}`（存在才带）；
  - 直播：`{item_guid, media_guid, ts:0}`（`liveRecordConfig` 提供-guid）。
- **去重**：对请求体计算**进度签名**（`createPlayerRecordSignature`），签名相同且距上次 ≤1 秒则跳过；直播版用 `{item_guid,media_guid,ts:0}` 序列化做签名，1 秒内同签名不重发。
- **触发后行为**：后端记录观看进度（继续观看列表、已看标记的数据来源）。失败时清空签名/时间戳以便下次重试；HLS 出现致命错误（HTTP≥400、notFound、serverError 等）时置 `recordBlockedByError` 并停止上报，避免拿坏流刷进度。
- **免签名**：`/play/record` 在免签名精确列表中（`Xh=[/task/running, /play/record, /subtitle/upload]`），但直播版 DELETE（删记录）不受豁免。

## 4. `POST /media/p`（media.transcodeStatis）—— 播放统计（30 秒，仅转码会话）

- **周期**：`Rp = 30*1e3`（30 秒），播放器 chunk `bf29a647…B0WFpgby.js`（`Ke` 轮询 hook，`refreshDeps:[enabled, playLink]`）。
- **触发条件**：存在转码会话 `playLink` 时才真正发请求（`zp` hook：`await ye.play.transcodeStatis({req,reqid,playLink})`）。
- **直连播放（无 playLink）不发网络请求**：`Vp` hook 每 30 秒在浏览器本地构造同结构统计数据（`resolution` 取自 video 元素实际尺寸、`bitrate` 由已下载分片 `total*8/duration` 实时计算、`transcoded:false`），仅供信息面板渲染；`req/reqid` 字段只是形状占位。
- **请求体**（RPC 信封，`reqid` 固定值）：
  - 查询方向：`{req:"media.transcodeStatis", reqid:"1234567890ABCDEF", playLink:"..."}` → 询问后端当前转码会话状态；
  - 响应：`{resolution, bitrate, transcoded, video:{encoder,dynamicRange,decodeMethod,encodeMethod,transcodingRate,selectedGpu}, audio:{encoder,channels}, transcodingReason}`，驱动信息面板"播放信息/播放类型"（转码时还显示解码/编码方式、GPU、转码速率）。
- **触发后行为**：驱动播放器的"转码/直连"状态显示、画质信息与统计面板；`loadedmetadata` 事件也会触发一次立即刷新。
- **免签名**：`/media/` 前缀整体豁免 authx。
- **相关一次性控制（同路径 `/media/p`，用户/事件触发，非周期）**：
  - `media.resetQuality`：`{req, reqid:"…2s", playLink, quality, startTimestamp, clearCache:true}`（切画质，带当前进度做无缝衔接）；
  - `media.resetAudio`：`{req, reqid:"…2s", audioEncoder, channels, audioIndex, playLink, startTimestamp}`；
  - `media.resetSubtitle`：`{req, reqid, playLink, startTimestamp, subtitleIndex}`；
  - `media.quit`：播放器销毁/退出播放页时调用（`quitPlay`，带 Map 防重复），释放后端转码会话；
  - `media.checkPlayLink`：播放出错时校验播放链路，最多重试 3 次（响应 `errno===4100` 视为视频文件丢失）。

## 5. `POST /stream`（stream.playback）—— 直链过期续期（30 秒检查，按需续）

- **定时器**：`Qv = 30*1e3`（每 30 秒跑一次检查），播放器 chunk `bf29a647…B0WFpgby.js`（hook `ey`）。
- **触发条件**：`isDirectLinkEnabled`（直连播放模式）且播放器处于播放中；暂停/结束即停表。
- **判定逻辑**（每次检查）：
  1. 距上次刷新不足 `$v=30` 秒 → 跳过；
  2. 找到当前正在播放的 URL 对应的 `direct_link_qualities` 条目，取 `expired_at`；
  3. `已播放时长 + 30 ≥ expired_at`（距过期不足 `Zv=30` 秒）→ 才真正发起续期请求。
- **请求体**：`{media_guid, ip:客户端出口IP, header:{User-Agent:[浏览器UA]}, level:Required}`——后端做防盗链指纹校验后签发新直链。
- **触发后行为**：响应里拿新的 `direct_link_qualities` 和 `direct_link_audio_streams` 替换进 `streamData`，播放器无感续期；失败仅 `console.error("刷新直链数据失败")`，下个周期重试。
- **同接口的其它用途**：起播时首次拉流信息、串流失效后重拉（调试模式会延迟 5 秒）也走 `POST /stream`，非周期。

## 7. nginx 日志实测佐证（/usr/trim/nginx/logs/access.log，近 4000 条 /v/api 请求）

分析窗口约 35.5 小时（09-04 00:21 → 09-05 19:07），期间主要是**手机客户端**活动：

| 端点 | 客户端 | 实测行为 |
|---|---|---|
| `GET /media/range/:id` | FlyPlayer（Android 飞牛影视播放器） | 播放中连续 206 分块拉流，**中位间隔 3 秒**（单块 1.4MB～79MB），等效持续流式拉取 |
| `GET /play/list` | Dart/3.11（飞牛影视 App） | 中位间隔 235 秒，App 前台/切页时刷新"继续观看" |
| `POST /play/info`、`GET /item/:id`、`POST /person/list/:id` | Dart/3.11 | 进入详情页时同秒并发批量请求（burst），非固定周期 |
| `GET /mediadb/list`、`/mediadb/sum`、`/tag/*` | Dart/3.11 | 页面切换/首次加载时请求，配合客户端缓存 |
| `GET /download/resolution/:id` | Dart/3.11 | 下载任务进度查询 |
| `GET /server/info` | Mozilla + curl | 本次分析的验证请求 |

网页端的 3 秒/15 秒/30 秒周期在本窗口内无浏览器会话活跃，未能从日志直接呈现，以静态分析还原的常量值（源码常量名 `PLAYER_RECORD_INTERVAL` 等自解释性强）为准。

## 8. 复现/调用提示

- 想在脚本侧模拟"任务进度轮询"：`GET /v/api/v1/task/running` 免签名，2.4 节的 authx 都不需要，直接 GET 即可（带 token 可拿完整数据）。
- 想模拟进度上报：`POST /play/record` 同样免签名，body 用 `{item_guid, media_guid, ts:<秒>}`，注意 ≥1 秒间隔、进度变化才有效（服务端同样有签名去重逻辑）。
- 完整签名算法与请求头见 [飞牛影视API文档.md](E:\NAS\飞牛影视API文档.md) 第 2 节；可直接复用 `E:\NAS\verify_authx.py` 的 `build_authx()`。
