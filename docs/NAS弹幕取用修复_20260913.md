# NAS 已保存弹幕取用修复

基线：`b0192db`，分支：`fix/nas-danmaku-consumption-20260913`。本次改动在独立 E 盘工作树中完成，未覆盖原目录、运行中的 EXE 或遮罩实现。

## 原因与范围

播放器原来已经支持通过飞翔账号按「媒体绑定 + 单集条目 + 文件版本」获取 NAS 弹幕。但读取只有 1.2 秒完整预算，未关联、过期、网络失败均静默回退，弹幕来源页也没有显式 NAS 重试入口。

当前电脑保存的活动绑定为 Emby；如果只在飞牛连接的单集保存了弹幕，不会按节目名称跨到 Emby 自动复用。需要在实际使用的媒体连接对应资料页保存并确认。跨来源复用仍须先核验文件版本，本次没有放宽此规则。

## 改动

- Windows 播放设置 → 弹幕源：显示「NAS 已保存弹幕」、当前媒体连接与单集、读取状态。
- 「重新获取 NAS 弹幕」只读取当前绑定的 NAS 已保存资源，使用独立 12 秒上限，不搜索网站，不排后台任务，不回退弹弹play。
- 明确区分：未登录、未选择绑定、目录未同步、未保存关联、资源过期、服务关闭、超时、格式校验失败。
- 修复流式 HTTP 请求丢失错误码的问题：16 KiB 内仅解析安全机器码，不展示服务端错误详情。目录不存在的 404 可准确提示同步目录。
- 重试失败保留当前正在使用的弹幕；成功才替换。切集或换账号时不交付迟到结果。
- 自动起播仍沿用原 1.2 秒预算及原来源回退策略。
- Android/Windows 共用的 NAS 缓存读取和 payload 格式保持一致；Android 本次未增加原生重试按钮。

## 使用与回滚

独立构建命令：

```powershell
& E:\fly_play_recovere\.tools\portable-build\build-mask-p0-integrated.ps1 -ProjectDir E:\fly_play_recovere\.worktrees\danmaku-consumption-fix
```

构建后用本目录 `启动飞翔播放器_NAS弹幕修复.ps1` 打开修复版。原运行中的播放器不会被自动关闭。先关闭旧播放器，再启动此版本，避免同时编辑相同账号设置。

登录飞翔账号，选择保存弹幕时所用的媒体连接并播放同一集；打开播放设置 → 弹幕源 →「重新获取 NAS 弹幕」。未匹配提示应回到后台对应连接、单集和文件版本处理。

回滚可关闭修复版，继续使用原播放器 EXE；原目录和旧构建均保留。本次无数据库迁移，也未发布 NAS 资源或更改绑定。

## 未验证与限制

- 尚未进行 Windows 或 Android 两端实际视频播放验收，没有新实机截图或画面证据。单元/组件测试不能替代实机弹幕播放验收。
- 本次不让 NAS 弹幕跨账号、跨绑定或未核验的文件版本自动共用，也没有新增持久离线缓存。
- 12 秒上限覆盖 NAS HTTP 读取及解析；大资源在极慢外网仍可能超时，界面会显示重试信息。
- Release 构建成功不等于画面验收。
