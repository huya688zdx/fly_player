# 大屏海报浏览页响应式重设计

**日期：** 2026-07-28  
**状态：** 已批准，待实施计划  
**范围：** `PosterBrowseScreen` 的内容精简、共享展示语义、手机竖屏背景主导布局、手机弧形循环轮盘、大屏横屏竖版海报轨，以及页面专用素材补全。

## 1. 目标

现有海报浏览页把电影、剧集、季和单集统一显示为 16:9 缩略图，并额外展示媒体库分类行。单集缺少所属作品、季集和集名信息；电影与季没有使用更合适的竖版海报；评分原样展示时可能过长；页面还强制所有设备横屏，手机体验不合适。

本次重设计实现以下目标：

1. 页面只保留“继续观看”和“最近添加”两个分组。
2. 横屏与手机竖屏共享同一套作品 Logo、标题、季集信息、元信息、简介、评分和图片回退规则。
3. 大屏使用横屏沉浸布局和普通竖版海报轨。
4. 手机使用竖屏、背景主导布局，不显示中心大竖海报；底部使用可循环、可吸附的微曲海报轮盘。
5. 单集根据稳定的父级关系补齐所属剧 Logo、背景和季海报，不依赖全局标题模糊搜索。
6. 首屏不等待重素材补全；只补全当前项及相邻窗口，兼顾速度、流畅度和请求量。

## 2. 已确认的产品决策

| 决策点 | 结论 |
| --- | --- |
| 页面内容 | 只保留继续观看和最近添加，不显示媒体库分类行 |
| 横竖屏语义 | Logo、标题、季集文案、元信息、简介、评分和图片候选链全部共享 |
| 大屏形态 | 横屏沉浸式背景 + 左侧信息区 + 普通横向竖版海报轨 |
| 手机形态 | 竖屏背景主导，不显示中心大竖海报 |
| 手机轮盘 | 底部中间微微上拱的弧形海报带，可左右连续拖动和点击选中 |
| 分组控件 | 弱化后放在轮盘上沿，与海报带形成一个内容选择器 |
| 轮盘边界 | 首尾无缝循环，所有停止位置吸附到中心 |
| 轮盘点击 | 点击非中心海报先滚到中心；点击已居中海报进入详情 |
| 单集海报 | 单集竖版图优先，缺失时回退所属季海报，再回退所属剧海报 |
| Logo | 电影使用自身 Logo；单集和季优先使用所属剧 Logo；缺失或加载失败时回退文字作品名 |
| 评分 | 最多保留一位小数；非法或空值隐藏 |
| 补全策略 | 轻量列表先展示，当前项与前后各两项按需补全 |

## 3. 内容与共享展示模型

### 3.1 页面分组

页面加载两个独立数据源：

1. 继续观看；
2. 最近添加。

任一分组为空或加载失败时，该分组隐藏，另一分组仍可正常使用。仅有一个分组时不显示无意义的切组控件。两个分组都为空或都失败时显示错误状态和重试入口。

加载器不再调用 `getCatalogs()` 或 `getCatalogPreviewItems()`，也不再构建媒体库分类行。

### 3.2 统一展示模型

横屏与手机竖屏都消费页面专用的统一展示模型。模型至少承载：

- 条目 ID、媒体类型、所属剧 ID 和原始卡片；
- 作品名、本集名称；
- 季号、集号和格式化后的季集文案；
- 背景图候选链；
- Logo 候选链；
- 轮盘或海报轨使用的竖版海报候选链；
- 格式化后的评分、年份、题材、时长、清晰度和简介；
- 续播位置与总时长；
- 播放和详情动作所需的稳定标识。

布局组件不得自行按后端类型拼接这些字段。横屏和竖屏的差异仅限布局与动效，不得形成两套内容语义。

### 3.3 文案规则

- 单集主内容：所属作品名或作品 Logo。
- 单集副信息：`第 X 季 · 第 Y 集 · 集名`；缺失部分按已有字段收缩，不能留下重复分隔符。
- 季副信息：`第 X 季 · 共 N 集`；集数缺失时只显示季号。
- 剧集副信息：展示已有季数、集数等信息。
- 电影不显示季集行。
- 简介横屏最多两行；手机根据可用空间显示一至两行，并优先保留 Logo、季集信息和核心元信息。
- 所有用户可见文案通过 `AppLocalizations` getter 获取，不引入硬编码中文或 `_t` 间接层。

### 3.4 评分格式

评分解析为数值后最多保留一位小数：

- `9.123` → `9.1`；
- `9.0` → `9`；
- 已是整数时不补 `.0`；
- 空值、非数字和无效数值不显示评分。

信息区和海报角标复用同一格式化结果，禁止各自处理原始评分。

## 4. 素材补全与反推

### 4.1 原则

素材补全必须基于稳定 ID 和明确父子关系，不进行全局标题模糊搜索。标题匹配容易把重名或相近作品的素材串入当前条目，因此不纳入本期方案。

页面首屏不等待补全。列表已有字段先生成可展示模型；素材补全完成后再安全更新对应条目。

### 4.2 父级关系反查

单集补全过程：

1. 使用当前单集已有的 `seriesId` 或飞牛祖先关系定位所属剧；
2. 调用公共后端详情接口获取所属剧详情，补齐作品名、Logo、背景和剧集海报；
3. 调用季列表接口，根据 `seasonNumber` 精确匹配所属季；
4. 使用匹配季的海报作为单集竖版图缺失时的首要回退；
5. 稳定 ID 缺失或反查失败时，只使用当前列表已有数据并进入普通回退，不做名称猜测。

Emby/Jellyfin 使用单集的 `SeriesId`；飞牛使用已有祖先关系。后端差异由补全器或后端提供的数据适配承担，页面布局不出现后端分支。

### 4.3 图片候选链

**背景图：**

1. 当前条目背景；
2. 所属剧背景；
3. 当前条目主图；
4. 所属季海报；
5. 所属剧海报；
6. 动态纯色背景。

**Logo：**

1. 当前条目 Logo；
2. 所属剧 Logo；
3. 文字作品名。

**轮盘或海报轨竖版海报：**

1. 当前单集明确的竖版图；
2. 所属季海报；
3. 所属剧海报；
4. 当前主图；
5. 纯色占位。

“当前单集竖版图”必须由明确图片语义或可靠尺寸判定确认。横版剧照不能因为恰好位于 `primaryImage` 就被当作竖版海报强裁切。

### 4.4 按需补全窗口

1. 两个列表请求完成后立即构建页面。
2. 当前中心项以最高优先级补全。
3. 后台预取中心项前后各两项。
4. 拖动轮盘或海报轨时不触发逐项补全。
5. 吸附完成后更新中心项并移动预取窗口。
6. 快速滑动期间，中间经过但未吸附的条目不触发补全。
7. 旧请求返回时只允许写入它自己的缓存项，不能覆盖当前焦点。

### 4.5 缓存

- 缓存键包含后端类型、服务会话标识和条目 ID。
- 同一缓存键的并发补全合并为一个进行中的 Future。
- 失败结果采用短期负缓存，允许稍后重试。
- 后端或账号切换后不复用旧会话素材。
- 缓存采用有界最近使用策略，只保留当前两组和近期邻近条目，不能随无限轮播持续增长。

## 5. 大屏横屏布局

### 5.1 页面结构

- 页面保持横屏沉浸模式。
- 聚焦条目的横版背景铺满整页。
- Logo 位于左侧信息区顶部；无 Logo 时在同一语义位置显示文字作品名。
- Logo 下依次展示季集信息、评分与媒体元信息、简介、播放和详情按钮。
- 分组控制与下方海报轨关联并弱化显示，不与 Logo 抢夺顶部主视觉。
- 下方使用普通横向竖版海报轨，不使用手机弧形透视效果。

### 5.2 海报卡

- 所有媒体类型统一使用竖版卡片。
- 作品名和副信息固定在海报下方，不覆盖图片。
- 继续观看卡保留底部进度条。
- 聚焦项使用轻微放大、描边和亮度变化，不遮挡文字。
- 点击非聚焦海报先将其滚到中心；点击已聚焦海报进入详情。

### 5.3 背景与信息切换

拖动期间保持当前背景、Logo 和信息不变。轨道吸附完成后才更新聚焦项，并使用交叉淡入切换背景；Logo 和文字采用较短淡入与轻微位移动画。动态取色只对最终聚焦背景执行。

## 6. 手机竖屏布局

### 6.1 页面结构

- 手机进入页面时保持竖屏，不显示中心大竖海报。
- 横版背景图占据主要视觉区域，尽量展现画面内容。
- 作品 Logo 放在背景安全区域；默认位于可读性较好的左侧或左下信息区，并限制最大宽高。
- Logo 下展示季集信息和媒体元信息；简介仅在空间允许时显示。
- “继续观看 / 最近添加”作为弱化分组控制，放在弧形轮盘上沿。
- 底部仅保留小型微曲海报轮盘，用于浏览和选择条目。

Logo 的安全区域由布局约束和渐变可读层保证。本期不做图片主体识别或每张背景的自动避让分析。

### 6.2 弧形循环轮盘

- 海报沿一条中间微微上拱的弧线排列。
- 中心海报略高、略大、最亮，并拥有最高绘制层级。
- 两侧海报随距离中心增加而逐渐下沉、缩小、旋转和压暗。
- 海报间允许轻微搭接，形成连续轮盘，不形成独立网格。
- 手指左右拖动时位置、缩放、旋转、亮度和层级连续跟手变化。
- 松手后根据拖动距离和速度选择目标项，并吸附到中心。
- 点击侧边海报会动画滚动到中心。
- 点击已经居中的海报进入详情。

### 6.3 首尾循环

轮盘使用虚拟页索引映射真实数据索引，不复制无限数据：

- 初始虚拟页位于可双向滑动的中间区间；
- 虚拟索引通过取模映射到真实条目；
- 接近虚拟边界时仅在动画停止后跳转到等价中间页；
- 单项列表不启用循环动画；
- 双项列表可循环，但限制同时渲染的重复副本，避免视觉异常；
- 缓存和展示模型仍以真实条目 ID 为键，不以虚拟页号扩张。

### 6.4 分组切换

- 分组控件位于轮盘上沿，当前分组清晰但不过度强调，另一分组降低不透明度。
- 点击分组名称切换继续观看与最近添加。
- 每个分组独立记忆自己的真实选中项或中心索引。
- 切组后立即显示该组已有缓存内容，并补全中心项及前后各两项。

## 7. 响应式与方向策略

- 手机竖屏判定：当前尺寸为竖向且最短边小于 `600dp`。
- 手机进入页面时锁定竖屏，避免传感器旋转后在同一会话中突然切换布局。
- 其他设备使用横屏沉浸布局并锁定横屏。
- 页面退出时解除页面施加的方向锁，恢复应用默认方向策略和 `edgeToEdge` 系统 UI。
- 正常返回、异常退出和页面销毁都必须有恢复兜底，不能把全应用留在错误方向或沉浸状态。

## 8. 动作行为

- 播放按钮直接播放当前聚焦条目。
- 电影等单条目复用现有 `ItemPlaybackLauncher`。
- 剧集复用现有系列播放目标解析和原生壳反向通道绑定。
- 单集详情入口定位到所属剧详情，以保留选集能力；稳定所属剧 ID 缺失时再按现有单条目详情行为降级。
- 所有点击动作继续使用现有并发闸门，避免转场期间重复 push 或重复绑定反向通道。

## 9. 异常与降级

- 单个分组失败时隐藏该组，另一组继续工作。
- 两组均不可用时显示本地化错误与重试入口。
- Logo 请求失败时按候选链回退，最终显示文字标题。
- 背景请求失败时继续尝试候选，最终显示动态纯色。
- 海报请求失败时继续尝试季、剧和当前图候选，最终显示纯色占位。
- 素材补全失败不得阻止轮盘滚动、分组切换、详情或播放。
- 快速切组、快速滑动和页面退出后，过期异步结果不得更新当前画面。
- 图片候选切换不得重置轮盘索引或分组选中项。

## 10. 性能约束

- 首屏只等待继续观看与最近添加列表，不等待详情、季列表或 Logo。
- 拖动过程中不发网络请求、不执行动态取色。
- 背景、Logo 和海报分别请求适合显示尺寸的图片，避免小组件解码全尺寸背景。
- 背景继续采用单图交叉淡入，不引入 `BackdropFilter`、实时模糊或多层全屏离屏合成。
- 弧形轮盘使用合成友好的位移、缩放、旋转、透明度或颜色滤镜；卡片基础布局尺寸保持稳定。
- Logo 复用现有详情页 Logo 候选加载机制，并限制解码尺寸。
- 相邻预取固定为前后各两项；如实机性能不足，优先降低阴影与亮度滤镜开销，不减少中心吸附准确性。

## 11. 测试设计

### 11.1 数据与模型单测

- 只生成继续观看和最近添加两个分组。
- 空组隐藏，且加载器不调用目录和目录预览接口。
- 电影、剧集、季和单集生成正确标题与副信息。
- 单集正确生成季号、集号和集名组合，缺失字段不留下多余分隔符。
- 评分整数、小数、长小数、空值和非法文本格式正确。
- 横屏与竖屏消费同一个展示模型，不存在两套格式化规则。

### 11.2 素材补全单测

- 当前条目素材优先于父级素材。
- 单集可通过稳定所属剧 ID 补齐 Logo 和背景。
- 季号可精确匹配所属季海报。
- 横版剧照不被误判为竖版轮盘海报。
- Logo 缺失或失败时回退文字标题。
- 同条目并发补全请求被合并。
- 只预取中心项前后各两项。
- 旧请求不能覆盖新焦点。
- 后端会话之间缓存隔离。
- 单项失败不影响其他条目。

### 11.3 轮盘与组件测试

- 虚拟索引正确映射真实索引。
- 首尾循环后真实选中项正确。
- 任意松手位置最终吸附到中心。
- 点击侧边项滚动到中心，点击中心项触发详情。
- 中心项始终拥有最高层级。
- 单项与双项列表不产生重复绘制异常。
- 两个分组分别记忆选中位置。
- 分组仅剩一个时隐藏切换控件。

### 11.4 响应式与方向测试

- 手机竖屏使用背景主导和弧形轮盘布局。
- 横屏或非手机设备使用大屏横向海报轨布局。
- 横竖屏均展示 Logo 或一致的文字回退。
- 页面进入、正常退出和销毁兜底均恢复正确方向与系统 UI。

## 12. 实机验收

分别在飞牛、Emby 和 Jellyfin 验证：

1. 单集所属剧 Logo、背景和季海报反推准确；
2. 电影、季、剧集和单集在大屏海报轨中均使用合理竖版素材；
3. 手机背景拥有足够展示面积，Logo 不遮挡主要信息且无 Logo 时文字回退自然；
4. 轮盘连续拖动、快速甩动、跨越首尾和点击侧边项后均准确吸附中心；
5. 快速切组不串背景、不串 Logo、不丢分组位置；
6. 弱网下首屏能先显示已有素材，补全失败不阻塞操作；
7. 连续浏览无明显内存增长和掉帧；
8. 手机系统返回手势与轮盘左右拖动不产生异常冲突；
9. 大屏进出横屏及手机进出竖屏后，应用其他页面方向正常。

## 13. 非目标

- 不做全局标题模糊搜索或跨作品素材猜测。
- 不做背景图主体识别、人物检测或 Logo 自动避让算法。
- 不改播放器内部逻辑、选集协议或下载功能。
- 不在大屏版加入手机弧形透视轮盘。
- 不恢复媒体库分类行。
- 不引入玻璃模糊、实时背景滤镜或自动轮播。
