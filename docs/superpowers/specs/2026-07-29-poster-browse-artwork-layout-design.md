# 大屏海报浏览素材与布局修复设计

## 目标

修复海报浏览页在飞牛后端下继续观看条目使用单集截图、剧集横版背景与标题 Logo 缺失、错误展示“最近添加”的问题，同时稳定信息区位置，改善手机背景清晰度和轮播卡片间距，并控制详情请求、图片解码与预取成本。

## 范围

本次只修改海报浏览页及其后端适配数据链，不调整普通首页、详情页和播放器。Emby 等支持最近添加的后端继续保留现有语义。

## 根因

1. 飞牛继续观看列表把 `MediaLibraryItem.ancestorGuid` 直接映射为 `MediaItemCard.seriesId`。对单集而言，可靠的剧集 ID 是以当前条目 `guid` 请求播放信息后得到的 `grand_guid`，因此现有补全逻辑可能查询错误父级。
2. 海报浏览展示模型把单集卡片图片排在剧集图片之前。即使父级详情成功返回，单集截图仍会先被背景或海报组件使用。
3. 第二栏无条件调用 `getLatestItems()` 并显示固定的“最近添加”标签，但飞牛官方数据结构并不存在这个首页栏目。
4. `PosterBrowseMediaInfo` 根据 Logo、文字标题和元数据的实际高度自然排版，Logo 迟到或候选变化会推动下方内容。
5. 手机背景与大屏共用全屏 `BoxFit.cover` 和固定大图请求策略。竖版素材在横屏中会被过度放大裁切，低质量源图的模糊被进一步放大。
6. 手机弧形轮播卡片默认宽度约为 116，固定中心间距为 220，导致相邻卡片大部分落在屏幕外。

## 数据设计

### 飞牛继续观看父级解析

飞牛继续观看条目保留真实单集 `guid` 作为播放目标。素材补全时以该 ID 获取播放信息，并使用非空且不同于条目 ID 的 `grand_guid` 作为剧集 ID；原始 `seriesId` 仅作为接口失败时的兜底。

解析后的剧集 ID 用于读取剧集展示详情，取得剧集名称、竖版封面、横版背景和标题 Logo。请求结果保存在现有会话级补全缓存中，同一条目和同一剧集的并发请求合并。播放按钮始终使用原始单集卡片，不会因为展示父级素材而改为播放剧集 ID。

### 素材优先级

对单集继续观看条目采用以下顺序：

- 卡片竖版海报：剧集竖版封面、对应季封面、条目其他竖版候选、单集主图。
- 大屏背景：剧集横版背景、条目详情横版背景、卡片横版背景、剧集封面、季封面、单集主图。
- 标题 Logo：剧集 Logo、条目 Logo；两者均不存在或加载失败时显示文字剧名。
- 标题：剧集详情标题、单集的剧集副标题、单集标题。

电影和独立条目继续优先使用自身详情素材，不套用剧集优先级。

### 第二栏来源

海报浏览行增加可携带后端标题的媒体库行：

- 飞牛：加载媒体库列表，按后端顺序选择首个类型为 `Series` 的媒体库；标签使用该媒体库的 `title`，条目通过其 `id` 调用 `getCatalogPreviewItems()` 获取。
- 飞牛没有 `Series` 媒体库或该库为空时，仅隐藏第二栏，不影响继续观看。
- Emby 等其他后端继续调用 `getLatestItems()` 并显示本地化“最近添加”。
- 两个数据源独立失败；任一行失败只隐藏该行，全部为空才显示整页加载失败。

## 布局设计

### 固定信息区

共享信息组件为 Logo/文字标题提供固定高度的标题槽位。Logo、文字回退和加载中的空状态都占用相同高度，下方副标题、评分标签、简介和按钮从固定锚点开始布局。

文字标题限制最大行数并使用省略号，不能突破槽位。大屏与手机使用各自的槽位尺寸，但同一设备形态内切换条目时位置不变化。

### 手机横屏背景

手机横屏选择 `posterImages` 而不是 `backgroundImages` 作为背景来源。竖版封面按可用高度等比缩放并靠右呈现，不用 `BoxFit.cover` 横向铺满；左侧及未覆盖区域由黑色底色和现有渐变遮罩承接，保证文字可读。

手机竖屏与大屏继续使用各自既有视觉方向，但图片请求尺寸改由实际渲染区域和设备像素比计算。解码尺寸设置上限，避免既把小图过度放大，也避免下载和解码远大于屏幕的大图。不引入实时高斯模糊。

### 手机轮播间距

弧形轮播不再固定使用 220 的中心间距。竖屏根据卡片宽度和可用宽度计算，目标约为卡片宽度的 1.25 到 1.35 倍；横屏可适度放宽，但必须保证相邻卡片清晰可见。

保留现有弧形纵向偏移、缩放、旋转、循环和中心吸附。卡片去重半径与同时绘制数量不增加。

## 性能设计

- 继续使用焦点稳定后再补全详情，快速滑动期间不触发每一帧网络请求。
- 补全缓存继续按会话隔离，使用 LRU、并发 Future 去重和失败短 TTL。
- 飞牛父级 ID 与剧集详情按条目懒解析，不在首屏批量加载全部剧集详情。
- 行条目维持 20 个上限。
- 大屏保留焦点附近窗口预取；手机仅预取当前项相邻素材，并使用与渲染区域匹配的解码宽度。
- 条目切换仍使用 generation 校验，过期请求完成后不得覆盖当前焦点。
- 不增加模糊滤镜、全屏离屏图层或新的常驻动画。

## 错误与回退

- `getPlayInfo` 失败：使用卡片已有 `seriesId`；仍无法得到剧集 ID 时只展示条目自身信息。
- 剧集详情失败：保留单集播放与详情入口，图片依次回退到季和条目候选。
- Logo URL 加载失败：同一槽位显示文字标题，不改变后续布局位置。
- 媒体库列表或剧集库预览失败：隐藏第二栏并记录现有吞错日志。
- 图片候选加载失败：继续使用现有候选链逐个回退，全部失败时显示纯色与渐变背景。

## 测试设计

采用测试驱动方式逐项补回归测试：

1. 飞牛单集按条目 ID 解析 `grand_guid`，使用正确剧集详情，且播放卡片 ID 不变。
2. `grand_guid` 缺失或请求失败时使用已有关系并安全回退。
3. 单集展示的海报、背景、Logo 和标题候选顺序符合本设计；电影顺序不变。
4. 飞牛第二栏选择首个 `Series` 媒体库、透传后端标题和媒体库 ID，不调用 `getLatestItems()`。
5. 非飞牛后端继续返回“继续观看 + 最近添加”。
6. 固定标题槽位在有 Logo、无 Logo和 Logo 加载状态下保持下方组件纵坐标一致。
7. 手机横屏使用竖版海报请求并采用非铺满适配；大屏仍使用横版背景请求。
8. 手机轮播在 390 宽竖屏和常见横屏尺寸下相邻卡片可见、无重叠和溢出。
9. 请求合并、LRU、失败短缓存、过期结果隔离和预取窗口测试保持通过。

## 验收标准

- 飞牛继续观看单集显示对应剧集封面，不以单集截图作为首选卡片。
- 选中单集时，大屏优先显示剧集横版背景和标题 Logo。
- Logo 出现或消失不会让评分、简介和按钮上下跳动。
- 飞牛不再显示“最近添加”，第二栏名称与内容跟随后端首个剧集媒体库。
- 手机横屏背景使用剧集竖版封面且不过度放大，画面清晰度不因强制铺满进一步恶化。
- 手机轮播相邻卡片间距明显收紧，同时保持弧形层次和操作行为。
- 针对性测试、完整 `flutter test` 与 `flutter analyze` 均通过。
