# 平台自适应、图片优先的首页设计

日期：2026-08-16  
状态：已确认，等待书面规格复核

## 1. 背景

当前首页把飞牛、Emby、Jellyfin 的数据套进同一组固定尺寸组件，产生了几类明显问题：

- 飞牛媒体库入口的多海报簇被压缩，Emby/Jellyfin 只有一张入口图时又会变成“大色块中漂着一张小图”。
- 媒体库入口和继续观看使用固定卡宽，窄屏会裁切，宽屏又不能利用空间。
- Jellyfin 继承 Emby 的 `/Items/Resume` 请求，但 Jellyfin 更稳定的续看语义是 `/Users/{id}/Items?Filters=IsResumable`；当前实机已出现首页续看空列表。
- 动态取色直接覆盖过大的界面面积，强调色和文字色没有形成稳定的语义对比，视觉显旧且部分文字不清楚。
- 长按菜单手工计算文字缩放后又被 Flutter 的 `TextScaler` 二次缩放，按钮过高、字体过大。
- 首页底栏使用 `extendBody: true`，滚动内容没有预留对应的底部安全距离，最后一排内容会被遮住。

本设计保留动态取色和现有后端抽象，重做首页的展示编排、响应式尺寸、文字层级和点击衔接。

## 2. 已确认的产品决策

1. 采用“共享渲染器 + 平台展示配置”：三种后端共用组件、颜色、字体和交互语义，但区块顺序及媒体库卡片形态可以不同。
2. 图片是首页的主要信息载体。存在服务端图片时使用真实图片铺满卡片，不再把小图放进大面积纯色容器。
3. 动态取色只控制背景氛围、表面层级、进度、选中态和小面积关键操作，不用强调色铺满大按钮或大卡片。
4. 媒体卡主体进入详情页；卡内独立播放按钮直接播放或续播；长按打开操作菜单。
5. 继续观看只存在于首页，不新增“全部继续观看”页面，也不显示“查看全部”。
6. 继续观看不能固定双卡。卡宽、列数和分页数量必须根据当前可用宽度、分屏状态、横竖屏和文字缩放动态计算。

## 3. 目标与非目标

### 3.1 目标

- 不同后端在同一 Fly 视觉系统下使用更适合自身数据的首页编排。
- 手机、宽屏手机、横屏、折叠屏、平板和多窗口中都不裁切卡片，也不浪费横向空间。
- 首屏能同时看到多个继续观看项目，并保留标题、季集、剩余时间、进度和直接播放能力。
- 图片、动态颜色和文字在明暗主题下都具备稳定的可读性。
- 首页到媒体库、详情页和播放器的去向明确；返回后恢复位置并刷新受影响的数据。
- 修复 Jellyfin 继续观看为空、长按菜单文字异常和底栏遮挡。

### 3.2 非目标

- 不创建继续观看聚合页或新路由。
- 不允许用户自定义拖拽首页区块顺序。
- 不重做详情页、播放器或媒体库列表页的信息架构。
- 不替换现有 `palette_generator`、动态主题缓存或媒体图片请求体系。
- 不在本轮引入新的跨后端持久化首页缓存。

## 4. 架构

### 4.1 平台展示配置

在展示层新增不可变的 `HomePresentationProfile`，通过 `MediaBackendKind` 选择配置。配置只描述展示，不发请求，也不包含后端原始字段。

配置至少包含：

- `sectionOrder`：首页区块顺序。
- `catalogStyle`：媒体库入口使用海报簇、横向图片或图片网格。
- `continueStyle`：继续观看的图片比例、理想卡宽和最大条目数。
- `showsSummary`、`showsNextUp`、`showsLatest`：可选区块开关。

页面不得在各个 Widget 内散落 `if (kind == ...)`。后端差异集中在 `HomePresentationProfile.forKind()`，共享渲染器只消费配置和中立模型。

### 4.2 首页数据模型

将当前散落在 `MediaListScreen` State 中的数据整理为展示层快照 `HomeViewData`：

- `catalogs`
- `continueWatching`
- `summary`
- `nextUp`
- `latest`
- `catalogPreviewItems`
- 对应的图片请求映射

`MediaCatalog` 和 `MediaItemCard` 继续作为后端中立模型，不把 Emby/Jellyfin 原始 DTO 或飞牛私有字段传进 Widget。

### 4.3 组件边界

首页共享渲染器拆成职责单一的组件：

- `HomeCatalogSection`：根据 `catalogStyle` 渲染媒体库入口。
- `HomeContinueWatchingSection`：负责响应式列数、分页、进度和播放按钮。
- `HomeSummarySection`：展示收藏及类型计数。
- `HomeMediaRowSection`：渲染下一集、最新入库和各媒体库预览。
- `HomeSectionHeader`：统一标题、数量和间距；继续观看标题没有导航操作。

组件只接收数据、展示配置和回调，不直接访问 API、Provider 或 Navigator。

### 4.4 后端数据扩展

`MediaBackend` 新增默认返回空列表的 `getNextUpItems({int limit = 20})`。飞牛不需要实现；Emby/Jellyfin 通过 MediaBrowser 家族的 `/Shows/NextUp` 提供全局下一集数据。现有按具体剧集解析起播目标的 `resolveSeriesNextUpEpisode()` 继续保留，二者用途不同。

`EmbyApi.getNextUpEpisodes()` 将 `seriesId` 改为可选：详情页传入 series id，首页全局下一集不传。`getLatestItems()` 继续使用现有公共接口。这样首页加载器只依赖 `MediaBackend`，不读取具体 API 类型。

## 5. 平台首页编排

### 5.1 飞牛

1. 媒体库入口：保留飞牛可提供的多海报优势，使用图片铺满的海报簇入口。
2. 继续观看：非空时显示响应式横向分页区。
3. 收藏及媒体数量概览。
4. 各媒体库的海报预览行。

### 5.2 Emby

1. 继续观看。
2. 我的媒体：单张服务端图片铺满横向入口，不使用飞牛的微型海报簇。
3. 下一集。
4. 最近入库。
5. 各媒体库预览行。

### 5.3 Jellyfin

1. 继续观看。
2. 下一集。
3. 最近入库。
4. 媒体库图片入口。
5. 各媒体库预览行。

任一可选区块为空时整区隐藏，不保留空标题或骨架占位。平台编排决定首屏优先级，共享组件保证三种后端仍属于同一套 Fly 设计系统。

## 6. 响应式尺寸规则

### 6.1 继续观看

继续观看由 `LayoutBuilder` 获取区块的真实内容宽度 `W`，不使用设备总宽度，也不写死两列。默认间距为 `10dp`，理想卡宽约 `190dp`；文字缩放较大时提高理想卡宽。

列数和实际卡宽按以下规则计算：

```text
columns = clamp(round((W + gap) / (idealCardWidth + gap)), 1, 5)
cardWidth = (W - gap * (columns - 1)) / columns
```

典型结果是普通手机约 2 列、宽屏或分屏约 3 列、平板约 4–5 列；这是计算结果，不是断点硬编码。极窄窗口或大号辅助文字允许降为 1 列，以可读性优先。

具体要求：

- 最多加载并展示 8 条续看数据。
- 每页完整展示 `columns` 张卡，不露出被裁掉的半张卡。
- 数据多于一页时显示轻量页码指示；不足一页时不显示。
- 宽度变化后保留当前第一个可见条目的 id，再据此计算新页码，避免旋转或分屏后跳回第一条。
- 卡片图片比例为 `16:10`，优先使用横向剧照或 backdrop，缺失时回退 primary image。
- 文字区只显示一行标题和一行播放上下文：季集、剩余时间；超长文本省略。
- 进度条贴图片底部；播放按钮为小面积强调色圆形按钮。

### 6.2 媒体库入口

媒体库入口同样使用真实内容宽度计算列数。飞牛海报簇、Emby 横向图片卡和 Jellyfin 图片网格各有独立理想宽度，但共用同一尺寸计算器，保证：

- 卡片完整显示，不从屏幕右侧裁断。
- 图片至少占入口面积的三分之二。
- 名称叠在带渐变遮罩的图片下部，或紧邻图片显示。
- 单图后端不再渲染成大容器内的微型竖图。

## 7. 图片、动态颜色与文字

### 7.1 图片

- 继续观看优先 `backdropImage`；剧集缺 backdrop 时使用当前集剧照；最后才回退 primary image。
- 媒体库入口优先服务端提供的库图片；飞牛可组合最多 2–3 张海报。
- 图片失败或完全缺失时使用中性表面和媒体类型图标，不生成高饱和伪图片。
- 图片上的文字始终叠加固定方向的明暗渐变遮罩，不能仅根据图片平均亮度猜测文字颜色。
- 首页和详情页复用同一 `MediaImageRequest`/缓存键，为 Hero 过渡和返回体验预热图片。

### 7.2 动态取色

- 从现有动态主题获得 seed 后先限制色度和明度，再生成背景、普通表面和强调色。
- 背景与普通卡片表面使用低饱和 tonal color；强调色只用于进度、选中导航、播放键和小面积状态。
- 强调色上的前景色必须由亮度/对比度计算得到 `onAccent`，不能直接复用 `textPrimary`。
- 图片上的主文字使用高对比 `onImage`，元信息使用次一级透明度；危险操作使用独立 danger container/onDangerContainer。

### 7.3 字体

- 页面标题和区块标题：`FontWeight.w600`。
- 卡片标题和按钮：`FontWeight.w500`。
- 元信息和正文：`FontWeight.w400`。
- 不为常规中文标题统一使用 `w700`。
- 所有字号只声明基础字号，让继承的 `TextScaler` 缩放一次；禁止先乘缩放值再交给 `Text` 二次缩放。

## 8. 点击和返回衔接

- 媒体库图片入口：进入现有 `CategoryItemsScreen` 或对应嵌入式详情入口，携带媒体库 id、标题和图片上下文。
- 媒体卡主体：进入现有影片/剧集详情流程。单集继续观看卡仍按 `seriesId` 定位到剧集详情。
- 卡内播放按钮：直接按当前续看位置播放；无有效进度时从头开始。
- 长按卡片：打开收藏、标记已看、从头播放和移出继续观看等操作。
- 返回首页：保持纵向滚动位置、继续观看当前页和媒体库横向位置。
- 播放结束或从详情返回：只刷新继续观看、下一集及受影响的收藏/已看状态，不重建整个首页滚动树。
- 继续观看标题右侧只可显示总数或页码状态，不显示“查看全部”，也不注册二级页路由。

## 9. 长按菜单

`AppActionSheet` 改为紧凑的语义化操作面板：

- 标题居左或与内容对齐，基础字号约 `17–18sp`，字重 `w600`。
- 常规操作使用中性 surface container，不使用大面积强调色按钮。
- 普通窗口使用两列紧凑操作；窄屏或较大文字缩放时自动退化为单列。
- 单个按钮高度约 `48–52dp`，文字约 `15–16sp`、`w500`。
- 危险操作使用低饱和危险容器和高对比前景色；取消操作与业务操作保留间隔。
- 删除现有手工 `textScale` 乘法，避免重复缩放。

## 10. Jellyfin 继续观看修复

后端继续保留 `MediaBackend.getContinueWatching()` 公共接口。差异收敛在 API 风味层：

- Emby 继续使用 `/Users/{userId}/Items/Resume`。
- `JellyfinApi` 覆写 `getResumeItems()`，内部改调 `/Users/{userId}/Items`，参数使用：
  - `Filters=IsResumable`
  - `Recursive=true`
  - `IncludeItemTypes=Movie,Episode`
  - `SortBy=DatePlayed`
  - `SortOrder=Descending`
  - `Limit=20`
- `JellyfinMediaBackend` 继续复用 Emby 的中立卡片映射和横图回退，避免在 UI 中出现 Jellyfin 请求分支。
- 首页最终截取最多 8 条用于展示；后端保留较大的返回上限，便于过滤无效条目后仍有足够数据。

续看请求失败是可选区块失败：记录诊断信息并隐藏续看区，不能让媒体库和其它首页区块一起进入整页错误态。

## 11. 底部导航安全区

保留悬浮、半透明底栏外观，但首页滚动区域的底部 inset 必须包含：

```text
底栏高度 + 底栏外边距 + 系统 SafeArea.bottom + 内容间距
```

该值由底栏布局常量统一提供，首页不得再使用固定 `20dp` 作为最终底部 padding。最后一张卡必须可以完整滚动到底栏上方。

## 12. 加载、空状态和错误处理

- 首要数据（媒体库、续看、概览、下一集、最新入库）并行请求，各区块独立收敛错误。
- 媒体库预览行按库独立加载；单个库失败只隐藏或显示该行的重试状态。
- 第一次加载且所有主要数据都失败时才显示整页错误态。
- 刷新时保留已有内容，成功区块增量替换，避免页面闪空。
- 继续观看为空时整区隐藏，不用分类内容伪造续看；这能暴露真实的数据源问题，避免 Jellyfin 再被假数据掩盖。
- 图片加载失败只替换图片区域，不影响标题、点击和播放入口。

## 13. 测试与验收

### 13.1 单元测试

- `HomePresentationProfile` 对飞牛、Emby、Jellyfin 生成正确的区块顺序和媒体库卡片样式。
- 响应式尺寸计算覆盖 320、360、600、840dp、横竖屏和不同 `TextScaler`，验证列数、卡宽、间距及无负尺寸。
- 宽度变化时能根据第一个可见条目恢复正确页码。
- `JellyfinApi.getResumeItems()` 请求通用 Items 路径并携带 `IsResumable`、`DatePlayed` 等参数；Emby 仍请求 Resume 路径。
- Jellyfin 续看 DTO 正确映射标题、系列 id、季集、进度、时长和横向图片。

### 13.2 Widget 测试

- 三种后端首页按配置渲染不同区块顺序，但复用相同组件语义。
- 继续观看有 1、2、3、8 条时布局正确；超过当前列数时出现分页指示，不出现“查看全部”。
- 卡片主体、播放按钮和长按分别触发详情、播放和菜单回调，不互相误触。
- 媒体库入口在单图和多图数据下都铺满图片区域，不出现微型图片漂浮。
- 长按菜单在 1.0、1.3、2.0 文字缩放下无溢出，并在需要时从两列退为单列。
- 首页最后一排可滚动到底栏上方。

### 13.3 回归与人工验收

- 运行 `flutter analyze` 和全部 `flutter test`。
- 在飞牛、Emby、Jellyfin 三种真实连接上检查首页数据、图片和点击路径。
- 在窄屏手机、横屏、分屏/平行视界及平板宽度检查即时重排。
- 播放一个续看项目后退出，确认首页进度和顺序刷新，滚动位置不丢失。
- 使用浅色和深色动态 seed 检查标题、元信息、播放按钮和危险操作的对比度。

## 14. 完成标准

- 三种后端不再被迫使用相同的首屏编排和媒体库入口形态。
- 所有可用图片都以主要内容形式展示，缺图时才降级为中性占位。
- 继续观看在任意宽度下动态分列、完整显示卡片，最多展示 8 条且没有二级页入口。
- Jellyfin 能显示真实续看内容。
- 动态取色不再造成低对比文字或大面积高饱和色块。
- 长按菜单字体、按钮密度和对比度清晰稳定。
- 底部导航不遮挡首页最后一排内容。
- 现有媒体库、详情页、播放器和返回刷新流程无回归。
