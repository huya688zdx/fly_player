# 首页横向媒体架修正设计

## 目标

修正飞牛、Emby 与 Jellyfin 首页在真机上的共同问题：分页式横滑割裂、媒体库海报被挤压、固定蓝色强调元素、冗余数量与剩余时长、下载状态难读，以及 Jellyfin“下一集”把横图塞进竖版海报框。三个平台共享一致的信息层级，只在数据是否存在时决定区块是否出现。

## 统一信息结构

三个平台采用相同区块优先级：

1. 媒体库
2. 继续观看
3. 下一集
4. 最近添加
5. 媒体统计
6. 各媒体库内容预览

不存在的区块直接隐藏。平台仍由各自后端提供数据和图片，但不再为了制造差异而交换“媒体库”和“继续观看”的顺序。

所有首页区块标题只显示名称，不显示“5 个”“8 条”等数量。继续观看的次要信息只保留媒体类型或季/集信息，不显示“剩余 xx 分钟”。

## 横向浏览行为

媒体库、继续观看和下一集都使用横向 `ListView.separated`，不使用 `PageView`：

- 拖动距离与停止位置完全跟随手势，可以停在任意卡片之间；
- 一次滑动可以跨过多个项目；
- 不显示分页圆点或滚动条；
- 卡片宽度由当前可用宽度计算，并在手机与平板合理上下限内夹取；
- 手机端露出下一张卡片的一部分，明确提示仍可继续横滑；
- 保留现有纵向首页滚动物理和底栏安全留白。

`HomeAdaptivePager` 不再服务首页区块；若没有其它调用方，在回归测试更新后删除组件和只针对分页的测试。

## 卡片视觉

### 媒体库

媒体库入口改为“自然比例海报架”：

- 每个入口最多使用两张竖版海报，按接近 `2:3` 的自然比例显示，不再把 2–3 张海报横向压扁塞满 `3:2` 卡片；
- 两张图轻微错位叠放在动态主题的 `surfaceStrong` 底板上；只有一张时居中显示；
- 分类标题放在图片下方的独立区域，使用 `textPrimary`，不叠在复杂海报上；
- 底板边框使用动态 `accent` 的低透明度混合色；缺图时使用同一底板和媒体类型图标；
- 飞牛、Emby、Jellyfin 共用该形态，避免同一种入口在不同平台出现不必要的结构差异。

### 继续观看

继续观看保持横向 `16:10` 图片卡，但改为自由媒体架。进度条和播放按钮使用 `context.appColors.accent`，前景色通过背景亮度选择黑或白，不再读取可能未同步运行时取色的固定 `colorScheme.primary`。

下载状态恢复为深色半透明底上的“已下载”文字标签，保留可访问语义。卡片主体打开详情、播放按钮直接播放、长按打开操作菜单的边界不变。

### 下一集

“下一集”使用独立的横向剧集卡：优先使用 backdrop，再回退 poster；图片铺满 `16:9`/`16:10` 横向画面，标题与季集信息位于图片下方。它不再复用竖版 `MediaPosterCard`，因此不会出现横图被缩小后夹在蓝色竖框中央的问题。

“最近添加”和媒体库内容预览仍使用适合电影/剧集封面的竖版海报列表。

## 长按菜单边界修正

保留已经确定的两列/大字单列规则和中性动态色按钮。大字单列时，业务按钮高度随真实 `TextScaler` 增长，确保“从‘继续观看’中移除”等真实长文案不会被固定 50 高度截断。测试必须使用生产中的最长中文标签并检查文字与按钮边界。

## SHA-256 说明

本次交付不执行 APK SHA-256 摘要验证，也不把摘要作为完成条件。仓库中的 SHA-256 目前用于飞牛鉴权、弹幕 API 签名、凭据/缓存指纹和稳定标识，并不存在用户可见的“下载后 SHA-256 校验”功能；这些安全与标识用途不属于本次删除范围，避免误删后破坏登录、图片缓存或播放。

## 测试与验收

- Widget 测试验证三个横向区块不存在 `PageView`、分页指示器和数量文案，并能停在非整页偏移；
- 媒体库测试验证海报容器保持竖版比例、标题不覆盖图片、动态颜色来自 `AppThemeColors`；
- 继续观看测试验证无剩余时长、文字下载标签、动态色播放按钮与原点击边界；
- 下一集测试验证使用横向卡片与 backdrop 请求，不再出现竖版 `MediaPosterCard`；
- 长按菜单用 320 宽、2 倍字号和最长生产文案验证真实边界；
- 定向测试、`flutter analyze`、完整 `flutter test`、真机安装及日志复查全部完成；完整测试若仅保留已记录的基线无关失败，需明确记录；
- 不进行 APK SHA-256 校验。
