# 登录会话、HTTP 登录与下载刷新回归修复设计

## 背景

全项目评审修复计划中的批次 S 和批次 P 已落地，但现有实现产生了三个用户可见回归：

1. 普通接口偶发 401 或安全凭据读取瞬时失败时，应用会清空会话并退回登录页。
2. 飞牛登录页隐藏了协议状态，用户无法清晰、稳定地选择 HTTP 登录。
3. 下载页虽然收到下载服务通知，但行组件继续读取旧的不可变记录快照，下载字节数和进度不刷新。

本次只修复以上回归，不回滚批次 S 的安全存储目标，也不恢复批次 P 的整页高频重建。

## 根因

### 会话被意外清空

`FeiniuApi` 的 Dio 拦截器把任意请求的单次 HTTP 401 直接转换为 `NasProvider.logout()`。网络代理、反向代理、单个资源权限或临时服务端状态都可能产生 401，因此网络层不能据此直接修改全局会话。

批次 S 引入的 `MethodChannelSecureCredentialBackend` 在平台通道异常时返回空字符串，并永久切换到仅存在于当前 isolate 的内存后备。`NasProvider._loadSettings()` 随后把这个空字符串当成“凭据不存在”，覆盖当前内存 token；Android 端读取凭据时还会在任意异常后删除密文文件。这两条路径都会把瞬时读取故障放大成登出。

### HTTP 登录不可控

登录页内部保留 `_baseUrlScheme`，但地址字段会隐藏 `http://` 或 `https://`，页面也没有可见的协议选择控件。用户修改无协议地址时会沿用不可见的旧协议状态，无法确认最终请求使用 HTTP 还是 HTTPS。

### 下载数据不刷新

批次 P 用结构签名缓存下载列表，并用行级 `ListenableBuilder` 替代整页 `AnimatedBuilder`。`DownloadTaskRecord` 是不可变对象，下载服务更新进度时会用 `copyWith()` 替换记录。行级 builder 虽然重建，却仍闭包捕获结构快照中的旧记录，因此继续显示旧的 `downloadedBytes`。

## 方案

### 1. 会话错误处理

- 移除 `FeiniuApi` 普通请求拦截器中的直接登出副作用；401 继续作为错误返回调用方，由页面显示本次请求失败。
- 只有用户主动退出，或未来专门的会话校验明确判定 token 失效时，才允许清空登录状态。
- 安全凭据读取结果必须区分“读取成功但没有值”和“读取失败”。读取失败时保留 `NasProvider` 当前内存 token，不把会话覆盖为空。
- 平台通道异常不应永久降级为 isolate 内存存储；后续读取仍应能够重试原生安全存储。
- Android 安全存储遇到临时解密、文件或 KeyStore 异常时不删除密文。损坏数据的清理应由明确、可诊断的迁移或恢复流程处理。
- 飞牛旧会话与中立后端连接存储使用同一读取语义，避免两套会话状态出现不一致。

### 2. HTTP/HTTPS 登录

- 在飞牛服务器地址字段旁提供明确的 HTTP/HTTPS 协议选择，默认值由已保存地址决定；没有已保存地址时沿用当前默认 HTTP。
- 地址输入框显示主机、端口和路径，协议选择单独展示，最终提交时组合为完整 URL。
- 用户粘贴带 `http://` 或 `https://` 的完整地址时，以显式协议为准并同步协议选择。
- 登录历史回填时同时恢复地址和协议。
- Android 现有 `usesCleartextTraffic="true"` 与网络安全配置保持不变，因为底层已经允许明文 HTTP。
- 飞牛 FN Connect ID 的识别路径保持不变，不把纯 ID 强制当作普通 HTTP 地址。

### 3. 下载行刷新

- 保留列表结构签名，只在任务增删、状态、路径或总大小等结构变化时重建列表。
- 行级监听触发后，按记录 ID 从 `DownloadTaskService` 获取当前记录，再渲染进度、速度和转码状态。
- 若记录已被删除或已跨状态移动，结构监听负责重建列表；行组件在过渡帧中安全降级，不访问失效索引。
- 下载列表和下载分组详情页使用同一条“按 ID 解析最新记录”逻辑，避免其中一个页面继续持有旧快照。

## 数据与错误流

普通 API 请求失败时：

`Dio 401/网络错误 → AppException/DioException → 当前页面错误态或重试入口`

不会再经过：

`普通请求 401 → NasProvider.logout() → 清 token → AppGate 返回登录页`

安全存储恢复时：

`安全存储有值 → 恢复凭据`

`安全存储确认无值 → 按迁移标记处理旧值或保持未登录`

`安全存储读取失败 → 记录诊断信息并保留当前内存会话，稍后重试`

下载更新时：

`DownloadTaskService 替换记录并 notifyListeners() → 行级监听按 ID 读取最新记录 → 仅重建对应可见行`

## 测试策略

按 TDD 分三组提交：

1. 会话稳定性
   - 普通 API 返回 401 时不会调用登出或清空 token。
   - 安全存储读取失败时，已加载的内存 token 保持不变。
   - 安全存储后续恢复后可以重新读取，不会被永久锁定在内存后备。
   - Android 读取异常不会删除已有密文文件；能区分缺失与失败。
2. HTTP 登录
   - 保存的 HTTP 地址恢复为 HTTP 选择。
   - 无协议输入按当前选择组合，明确选择 HTTP 时不会被改成 HTTPS。
   - 粘贴显式 HTTP/HTTPS 地址会同步协议并保持主机、端口和路径。
   - 登录历史回填保持原协议。
3. 下载刷新
   - 下载服务用新不可变记录替换进度后，列表行显示新的已下载字节数和进度。
   - 下载分组详情页同样刷新。
   - 速度与转码进度仍保持行级局部刷新，列表结构不因每次进度通知而整体重建。

## 提交与验证

每个独立修复分别提交：

1. `fix(auth): prevent transient failures from clearing sessions`
2. `fix(login): restore explicit http protocol selection`
3. `fix(download): refresh rows from current task records`
4. 如文档登记不能与上述提交安全合并，再单独提交 `docs: record regression fixes in review plan`

验证至少包括相关 Flutter 单测、`flutter analyze`，以及可用条件下的 Android Kotlin 单测或 debug APK 构建。人工验证重点为断网/恢复、HTTP NAS 登录、下载中列表与详情页实时进度。

## 非目标

- 不在本次拆分 `FeiniuApi` 上帝类或完成批次 M 的全部服务层重构。
- 不引入自动刷新 token、连续 401 计数或新的后台会话探测协议。
- 不允许公网任意坏证书，也不放宽批次 S 的证书校验范围。
- 不恢复下载页整页高频监听。
