# 飞牛访问码适配设计

## 背景与目标

新版飞牛访问入口可在 NAS API 前增加访问码网关。未通过网关时，任意路径可能返回访问码 HTML 页面；通过后才能继续访问飞牛登录、媒体、图片、下载和播放接口。

本次改造目标是在保留旧版飞牛直连、FN Connect 和非飞牛后端现有行为的前提下，为所有使用飞牛 NAS 的同源网络链路增加可选访问码支持。访问码不得出现在日志、普通偏好设置、缓存键或自动化测试数据中。

## 已验证的服务端协议

目标服务的访问码页面公开了以下 App 模式协议：

- 请求头 `x-access-code`：访问码按 UTF-8 编码后进行 Base64 编码。
- 请求头 `x-access-source`：固定为 `app`。
- App 模式不依赖 Cookie，访问码请求头需随每个受网关保护的请求发送。
- 正确访问码可放行飞牛登录接口；错误访问码返回 HTTP `401`，网关也可能使用 `403` 或 `429`。
- 缺少访问码时，受保护路径可能返回 HTTP `200` 和访问码 HTML 页面。

已使用用户提供的临时凭据完成只读验证：访问码验证成功，飞牛用户名密码登录返回业务码 `0` 并签发非空令牌。验证过程没有输出 Cookie、NAS 令牌或凭据值。

## 方案选择

采用“App 请求头模式”，不采用 Cookie 会话或 WebView 登录：

- 请求头可以被 Flutter Dio、图片加载器、下载器、`MpvMediaSource` 和 Android 原生 HTTP 客户端共同消费。
- 不需要在多个 HTTP 客户端和 Flutter Engine 之间同步 Cookie 生命周期。
- 不引入 WebView，也不改变现有直连登录交互模型。

## 架构

### 会话状态

`NasProvider` 增加可选访问码状态，并负责运行时读取、启动恢复、安全持久化和登出语义。访问码与 NAS 密码一样受“记住密码”开关控制：

- 开启时，访问码单独写入现有安全凭据存储；SharedPreferences 只记录非敏感元数据。
- 关闭时，访问码保留在当前进程会话中以支持登录后的所有请求，但不持久化；应用重启后需要重新输入。
- 登出清除 NAS 令牌和运行时资源缓存，但保留用户明确选择记住的密码与访问码，沿用当前重新登录体验。
- 多 Flutter Engine 的 bootstrap 快照必须携带访问码，保证分屏和恢复后的请求头一致。

### 请求头构造

新增单一职责的访问码请求头构造逻辑，输入原始访问码，输出以下映射：

```text
x-access-code: <UTF-8 Base64 编码值>
x-access-source: app
```

空访问码输出空映射。该逻辑负责统一编码和头名称，调用方不得重复实现 Base64 规则。

`FeiniuApi` 在下列位置合并访问码请求头：

- 普通 Dio API 拦截器；
- 直连登录 Dio；
- FN Connect 解析后对最终飞牛 NAS 地址发起的同源请求；
- `buildSignedHeadersForUrl` 和 `buildPlaybackHeadersForUrl`；
- 飞牛图片、字幕和下载使用的独立 HTTP 客户端。

访问码只允许发送给与当前 NAS base URL 同源的 HTTP/HTTPS 地址。第三方直链、外部字幕地址以及夸克、UC 等存储服务不得携带访问码。原有 NAS token、`Trim-MC-token`、Authx、`mode=relay` 和 `entry-token` 规则保持不变，并与访问码头合并。

### 登录流程

飞牛登录表单新增“访问码（可选）”密码型字段。登录回调和 `loginWithBaseUrl` 增加可选访问码参数，直连和 FN Connect 候选登录均按同源规则携带访问码头。

登录成功后，`ConnectionScreen` 将访问码与其他飞牛会话数据一起交给 `NasProvider`。未启用访问码的服务器允许字段留空，并完全走旧版行为。

### 图片与主题取色

Flutter 图片请求继续通过 `MediaImageRequest.headers` 消费完整头集合。飞牛图片解析器不再只根据 token 构造图片头，而是合并同源访问码头。

Android 主题取色通道从只接收 token 改为接收完整图片请求头；原生 `ThemeColorSampler` 逐项加入安全过滤后的头，保证访问码后端的图片可采样，同时避免把同源凭据发送给外部 URL。

### 播放、原生代理与封面

播放 URL 的访问码头写入 `MpvMediaSource.headers`，沿现有 loadArgs JSON 进入 Android：

- mpv 直连加载使用完整 headers；
- `NativeMpvProxyServer` 重建 Authorization 和 Authx 时保留并转发访问码头；
- 清晰度切换、服务端播放会话、字幕下载和 seek 相关请求沿用同一头集合。

原生选集封面、听视频封面和媒体通知封面目前只消费 `imageAuth` token，需要扩展为完整图片头映射。Flutter 原生选集数据提供完整 `imageHeaders`，Android Glide 与媒体服务使用该映射加载图片；本地文件封面保持空头。

### 下载链路

`DownloadTaskService` 中复用 `FeiniuApi.buildPlaybackHeadersForUrl` 的请求自动获得访问码头。仍直接创建 Dio 并手工添加 token 的封面恢复路径改为使用统一的同源飞牛请求头，避免遗漏。

### 登录历史

`LoginHistoryEntry` 增加运行时访问码字段，但序列化 JSON 不写入访问码。`LoginHistoryStore` 使用由后端类型、地址和用户名派生的独立安全存储键保存访问码：

- 开启“记住密码”且访问码非空时写入；
- 关闭时删除对应安全凭据；
- 删除、截断或清空历史时同步删除访问码；
- 旧历史没有访问码时无损迁移为空值；
- 选择不同服务器历史记录时清空当前旧访问码，再回填所选记录的访问码。

## 错误处理

错误分类按以下优先级处理：

1. HTTP `401`、`403` 或 `429` 且命中访问码网关特征时，提示“访问码错误或已失效”。
2. HTTP `200` 但响应是访问码 HTML 挑战页时，提示“该服务器需要访问码”。
3. 已通过网关且飞牛登录返回账号鉴权错误时，沿用现有用户名或密码错误提示。
4. 网络、地址、证书和服务不可用错误沿用现有 `LoginErrorResolver` 分类。

访问码错误识别不得把所有 `401/403` 无条件归类为访问码错误；必须结合是否填写了访问码、响应内容类型或网关页面特征，避免遮蔽真正的 NAS 账号权限错误。

新增中英文及现有本地化变体所需文案，包括访问码字段、访问码必需、访问码错误或失效。日志只允许记录访问码是否存在，不记录原文或 Base64 值。

## 测试策略

### Flutter 单元与组件测试

- UTF-8 Base64 编码与固定请求头名称；
- 空访问码不生成请求头；
- 同源 NAS URL 携带访问码，第三方 URL 不携带；
- 直连登录、FN Connect 候选登录、普通 API、图片、下载和播放源合并正确头；
- 未启用访问码的旧后端行为不变；
- 网关 HTML、`401/403/429` 与普通账号密码错误正确区分；
- `NasProvider` 安全存储、启动恢复、多 Engine bootstrap 和登出语义；
- 登录历史保存、回填、删除、截断、清空及旧数据兼容；
- `MpvMediaSource` 映射往返保留访问码头。

### Android JVM 测试

- 原生代理过滤 hop-by-hop 头时保留 `x-access-code` 与 `x-access-source`；
- Authx 重签不会覆盖或丢失访问码头；
- Glide/主题取色/媒体服务使用完整图片头，并拒绝向非同源 URL 注入 NAS 凭据。

### 验证命令

实施完成后至少执行：

```bash
flutter test <相关测试文件>
flutter test
flutter analyze
flutter build apk --debug
```

若 Android 单元测试不由 Flutter 构建覆盖，额外执行项目对应的 Gradle JVM 测试任务。真实服务只做不输出敏感值的协议验收，任何真实地址和凭据都不得写入测试或仓库。

## 验收标准

- 未启用访问码的旧飞牛直连登录与全部现有功能不回归。
- 启用访问码的飞牛服务能登录并稳定完成列表、详情、搜索、图片、主题取色、下载、字幕、播放、切集、清晰度切换和后台媒体封面请求。
- 访问码错误、缺失与 NAS 账号密码错误能得到不同且准确的提示。
- 访问码仅在同源飞牛请求中出现，并只通过安全存储持久化。
- Emby、Jellyfin、FN Connect 边缘令牌和第三方媒体直链行为不受影响。

## 非目标

- 不修改飞牛服务端访问码协议。
- 不使用 WebView 管理直连访问码。
- 不为 Emby 或 Jellyfin 新增访问码字段。
- 不把访问码改造成通用代理凭据框架。
