# 海报浏览多媒体库与手机竖版背景修复设计

## 目标

修复海报浏览页在飞牛、Emby 和 Jellyfin 后端中的以下问题：

- 剧集竖版封面已经异步补全，但界面必须再点击一次分类才刷新。
- 页面只显示一个媒体库分类，遗漏后端中的“动漫 TV”等其他媒体库。
- 手机竖屏仍使用横版背景大图，裁切和放大后观感差、容易模糊。

修复后，“继续观看”固定在最前，后端返回的全部影视媒体库按原始顺序展示；手机横竖屏都使用剧集竖版封面作为背景；平板和电视仍使用横版背景大图。

## 已确认的根因

### 封面延迟刷新

焦点素材补全完成时，若当前焦点 generation 已经变化，代码只把结果写入 `_displayById`，没有调用 `setState`。因此缓存中已经存在正确的竖版封面，但界面没有重建；用户下一次点击分类触发重建后，封面才突然出现。

generation 校验本应只保护“当前焦点”相关副作用，例如当前背景和相邻图片预取，不能阻止已经完成的卡片素材更新自身显示。

### 媒体库被截断

数据加载层目前只取飞牛的第一个 TV/Series 库，Emby/Jellyfin 则只加载“最近添加”。同时横屏和手机布局都对行列表调用 `take(2)`。这两层限制共同导致后端其余媒体库永远无法显示。

### 手机竖屏图片来源错误

背景策略只在“手机且横屏”时选择 `posterImages`，手机竖屏仍走 `backgroundImages + BoxFit.cover`，因此横版大图会被明显裁切并放大。

## 数据模型与加载流程

### 行模型

`PosterBrowseRow` 增加媒体库标识和加载状态，使媒体库名称可以先显示、内容随后加载：

- “继续观看”行没有 `catalogId`，内容由现有续播接口提供。
- 每个后端媒体库对应一个 `catalog` 行，保存后端原始 `id`、`title` 和顺序。
- 媒体库行区分未加载、加载中、已加载和失败状态。
- 已加载但没有条目的媒体库仍保留分类入口，避免擅自改变后端返回的媒体库集合。

### 首屏加载

首屏并行请求“继续观看”和媒体库元数据，不等待所有媒体库内容：

1. “继续观看”有内容时固定为第一行。
2. 飞牛、Emby、Jellyfin 均调用公共 `MediaBackend.getCatalogs()`。
3. 后端返回的全部影视媒体库按原始顺序映射成分类行，不再按 `tv`、`series` 等类型截断。
4. 如果存在媒体库，后台预取第一个媒体库的前 20 个条目。
5. 若没有“继续观看”，第一个媒体库成为当前选中行，并立即加载。

“最近添加”不再作为海报浏览页的后端特例；该页统一以真实媒体库为分类来源。

### 按需加载与缓存

- 用户首次选择尚未加载的媒体库时，立即加载该库前 20 个条目。
- 同一媒体库的并发请求合并，避免快速重复点击产生重复网络请求。
- 成功结果在当前页面会话内缓存，重复切换不重新请求。
- 单个媒体库失败只影响该行；再次选择时允许重试，不清空其他行。
- 切换后端或连接会话时使用加载会话 token 隔离旧请求，旧会话结果不得写入新页面状态。
- 只为当前行创建图片组件，图片预取仍限制在焦点邻域，不因媒体库数量增加而批量解码所有封面。

## 界面行为

### 分类选择器

- 删除横屏与手机布局中的 `rows.take(2)`。
- 分类选择器改为固定高度的单行横向滚动列表。
- 分类数量或标题长度增加时只横向滚动，不换行，不推动下方海报轨道，也不改变信息区锚点。
- 当前媒体库加载中时，在原海报轨道区域显示轻量加载状态；不移动分类选择器和信息区。
- 已加载空库显示固定的空状态，不删除分类按钮或改变其他行索引。

### 素材补全刷新

任何属于当前加载会话的素材补全结果都通过 `setState` 更新对应卡片，即使请求完成时焦点 generation 已变化。

generation 只决定以下行为是否继续：

- 是否把该条目作为当前 settled item。
- 是否更新当前背景和 Logo。
- 是否预取该焦点的相邻图片。

这样快速滑动时不会让旧焦点夺回当前背景，同时已经补全的卡片会立即显示正确竖版封面，不需要额外点击分类。

## 手机背景策略

### 图片来源与适配

- 所有手机尺寸，无论横屏还是竖屏，背景来源都使用当前条目的 `posterImages`。
- 手机横屏保持 `BoxFit.contain + Alignment.centerRight`，竖版封面靠右完整显示。
- 手机竖屏使用 `BoxFit.contain + Alignment.topCenter`，竖版封面从顶部完整显示，底部由现有暗色渐变承接海报轨道。
- 不增加实时模糊层、双重图片层或额外常驻动画。
- 平板、电视及其他大屏继续使用 `backgroundImages + BoxFit.cover`。

### 清晰度与性能

- 手机背景请求宽度按实际渲染宽度和设备像素比计算，并设置合理上限，避免无意义地下载或解码超大图片。
- 手机背景预取半径保持为 1，只预取当前项相邻素材。
- 大屏横版背景维持现有尺寸上限和预取策略。
- `BoxFit.contain` 避免把低分辨率竖版封面强制铺满、裁切和进一步放大。

## 错误处理

- 媒体库列表失败时仍可显示已经成功加载的“继续观看”。
- “继续观看”失败时仍显示媒体库分类。
- 单个媒体库内容失败时保留分类入口并允许重试。
- 素材补全失败时沿用现有图片候选回退链，不影响播放和详情入口。
- 后端切换后的迟到请求通过会话 token 丢弃，避免跨后端污染同 ID 卡片。

## 测试设计

按测试驱动方式增加以下回归覆盖：

1. 飞牛返回电影、电视剧、“动漫 TV”等多个媒体库时，全部按后端顺序生成分类行。
2. Emby 与 Jellyfin 同样通过 `getCatalogs()` 生成全部媒体库，不再只生成“最近添加”。
3. “继续观看”存在时始终位于全部媒体库之前；不存在时第一个媒体库成为初始行。
4. 媒体库内容只在首次选择或首库预取时请求，同库并发请求合并，已成功加载后不重复请求。
5. 单库失败不影响其他库，再次选择能够重试。
6. 横屏与手机布局接收超过两个分类时不截断，并采用单行横向滚动选择器。
7. 素材请求在焦点 generation 变化后完成，卡片仍立即重建并显示补全封面，但不会覆盖当前焦点。
8. 后端会话切换后，旧请求结果不会写入新会话。
9. 手机横屏与竖屏均选择竖版封面；竖屏为顶部居中完整显示，横屏为右侧居中完整显示。
10. 平板和电视仍选择横版背景并保持现有解码尺寸上限。

## 验收标准

- 进入海报浏览页后，竖版剧集封面在补全完成时自动出现，无需点击分类刷新。
- 飞牛、Emby、Jellyfin 均显示后端返回的全部影视媒体库，包括“动漫 TV”等自定义名称。
- 多个分类不会换行或推动下方海报和信息区位置。
- 手机竖屏和横屏背景都使用当前剧集竖版封面并完整显示，不再使用横版大海报强制裁切。
- 每个媒体库最多加载 20 项，未访问媒体库不会批量加载内容或图片；重复切换不产生重复请求。
- 新增针对性测试、相关海报浏览测试与 `flutter analyze` 通过。
