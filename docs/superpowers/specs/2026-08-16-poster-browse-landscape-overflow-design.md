# 海报浏览短横屏溢出修复设计

**日期：** 2026-08-16

**状态：** 已批准

## 目标

修复海报浏览页在真机 `853 × 384` 逻辑像素横屏窗口中的底部溢出，同时保留海报尺寸、两行标题、一行副标题、分类选择器和横向滚动交互。正常高度的平板和电视布局保持不变。

## 日志与根因

Android 配置日志确认问题窗口为 `sw384dp w853dp h384dp 600dpi`。当前大屏布局固定占用：顶部 `16`、返回按钮 `48`、分类选择器 `48`、间距 `14`、海报轨 `280`、底部 `22`，合计 `428` 逻辑像素，因此在 `384` 高度中稳定产生 `44` 像素的外层 `RenderFlex` 溢出。

此前根据 `960 × 432` 测试误将海报轨从 `264` 增至 `280`，把真机原有的 `28` 像素溢出扩大为 `44` 像素。日志中旋转阶段还出现过 `89` 像素溢出；短横屏中信息面板被放进几乎为零的 `Expanded` 空间，是该瞬时错误的来源。

## 方案

1. 海报轨恢复为 `264` 逻辑像素，继续容纳 `116 × 174` 海报、两行标题和一行副标题。
2. 高度低于 `600` 的短横屏不构建媒体信息面板。该面板在现有布局中本来也没有足够空间可见，移除后可消除旋转阶段的内部溢出。
3. 当高度低于常规固定内容所需的 `412` 像素时，将顶部、底部和分类选择器至海报轨的间距统一压缩为 `8` 像素。真机高度预算为 `8 + 48 + 48 + 8 + 264 + 8 = 384`。
4. 高度达到 `600` 及以上时继续使用现有边距、信息面板和交互，不改变平板或电视视觉。

不切换手机弧形轮播，不缩小海报或字体，也不引入动态文字测量。

## 测试设计

采用测试驱动方式：

1. 用真机日志中的 `853 × 384` 窗口和应用实际约 `1.08` 文字缩放复现问题。
2. 修复前必须捕获 `RenderFlex` 溢出。
3. 修复后断言没有异常、海报轨仍高 `264`、媒体信息面板未构建、两行标题和副标题仍存在。
4. 在 `1280 × 800` 用例中确认媒体信息面板继续显示。
5. 运行海报浏览相关测试、静态分析，并在连接的真机上重新抓取日志和截图。

## 验收标准

- `853 × 384` 真机横屏不再出现黄色溢出条或 `RenderFlex overflowed` 日志。
- 海报宽高比、两行标题、一行副标题、进度条和横向滚动保持不变。
- 正常高度布局继续显示媒体信息面板。
- 定向测试与静态分析通过。
